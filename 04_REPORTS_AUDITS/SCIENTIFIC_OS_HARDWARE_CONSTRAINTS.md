# Architectural Report: Scientific OS Hardware & Runtime Constraints

This report outlines the critical physical and algorithmic constraints for the Scientific Computing Platform (Scientific OS), specifically focusing on VRAM arbitration, Just-in-Time (JIT) guarding, the division of logical vs. empirical provenance, and strict LLM output validation when integrating local Open-Weights models (e.g., Gemma 4 via Ollama) with heavyweight 3D pipelines (Blender, Meshroom, Unity).

---

## 1. Local VRAM Resource Arbitration & Time-Sharing

### The Challenge
A typical open-weights Large Language Model (e.g., Gemma 4 12B/27B) requires significant GPU VRAM to maintain long context windows (up to 256K). Concurrently, photogrammetry (Meshroom SfM/DepthMap) and 3D rendering (Blender Cycles) utilize CUDA/OptiX pipelines which also demand massive VRAM allocation (4GB to 12GB+). 

On a single consumer or developer GPU (e.g., 16GB-24GB VRAM), executing an LLM query concurrently with a 3D reconstruction task results in an out-of-memory (OOM) GPU collision or severe memory thrashing via PCIe system memory fallback.

### Mitigation: Aggressive VRAM Time-Sharing
The **Anti-Gravity Bridge** must manage LLM lifetime programmatically:
1. **Explicit Unload (keep_alive: 0):** When querying Ollama via `/api/generate` or `/api/chat`, the request payload must enforce a `keep_alive: 0` policy. This instructs the Ollama daemon to immediately release Gemma 4 from GPU VRAM after completing token generation.
2. **GPU Locks / Semaphores:** The Bridge must acquire a hardware lock before invoking execution adapters. If a Blender or Meshroom task is scheduled, all LLM inference operations are paused, and a force-unload query is dispatched to Ollama before starting the CUDA subprocess.

## 2. JIT Guarding vs. Static Cost Modeling

### The Challenge
Standard compilers estimate compilation cost statically based on code structure. However, in scientific data pipelines (e.g., Structure-from-Motion photogrammetry), execution complexity is highly data-dependent. A photogrammetry task's runtime is not linear with image count; it scales non-linearly with image resolution, feature density, and visual entropy. Furthermore, GPU and memory state are dynamic.

### Mitigation: Just-in-Time Telemetry Check
1. **Abstract Compiler:** The `Scientific Compiler` must remain hardware-blind. It designs a purely logical execution DAG using abstract resource tags (e.g., `RESOURCE_CLASS: HIGH_GPU`) instead of hardcoded hardware limits.
2. **JIT Guard in the Bridge:** Immediately before a job is dispatched from the queue, the Bridge queries the host environment (via `nvidia-smi` and `psutil`). If the current free VRAM or RAM is below the minimum safety threshold computed for the input payload size, the job is deferred in the Priority Queue until resources are freed.

## 3. Logical vs. Empirical Provenance

### The Challenge
A cryptographic hash (SHA-256) of input data combined with a Git commit hash is insufficient to guarantee bitwise reproducibility in stochastic, GPU-accelerated environments. Differences in thread scheduling, GPU temperature (thermal throttling), CUDA/cuDNN algorithms, and hardware float rounding order produce subtle bitwise differences in output meshes and generated datasets.

### Mitigation: Decoupling Provenance Types
1. **Logical Provenance:** Records the deterministic input properties—compiler AST parameters, prompts, input file hashes, and stochastic seeds. This defines the *intention* and *recipes*.
2. **Empirical Provenance (Telemetry Log):** Records the physical environment of the execution run—OS platform, exact GPU model, Nvidia driver/CUDA version, CPU thread count, and hardware execution timestamps.
3. **Validation Strategy:** Reproducibility is measured by *functional equivalence* (e.g., vertex density, volumetric deviation, biological sequence validity) rather than byte-for-byte SHA-256 identity.

## 4. Strict Validation of Probabilistic LLM Outputs

### The Challenge
LLM function-calling or JSON generation is stochastic and prone to syntax degradation or parameter drift. Directly parsing probabilistic outputs into target CLI execution blocks can break deterministic backend scripts (e.g., Blender python API scripts).

### Mitigation: Pydantic Schema Guards
1. **Schema Check:** All JSON structures generated by Ollama/Gemma 4 are validated against target AST/JSON Schemas using Pydantic models.
2. **Fail-Fast Policy:** If validation fails, the compiler attempts exactly *one* self-correction loop by prompt-feeding the validation error trace back to the LLM. If the second attempt fails, the compiler halts execution and falls back to a deterministic, safe default configuration.
